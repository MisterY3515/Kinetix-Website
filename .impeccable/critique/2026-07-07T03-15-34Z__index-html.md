## Anti-Patterns Verdict

**LLM assessment**: Most named AI-slop tells are genuinely absent, verified by grep, not just eyeballing — zero gradient-clipped text, glassmorphism confined to exactly the one permitted hero surface plus the functional nav blur, no tiny tracked eyebrows, no numbered 01/02/03 scaffolding, no side-stripe card borders. DESIGN.md explicitly says it's rejecting a "previous build's" over-decorated look, and the code has actually caught up to that spec — a rare case where the aspirational design doc matches shipped CSS. Two real misses stand out: the four feature cards (`index.html:130-165`) are structurally identical icon+heading+paragraph blocks — literally the anti-pattern PRODUCT.md's own Anti-references section names — and the hero's signature code showcase has no `overflow-x` escape valve at narrow viewports, risking silent clipping on the one component meant to be the credibility anchor. Second-order risk: despite avoiding every individual named tell, the dark-void + cyan-glow + blurred-badge aesthetic is itself now a recognizable "AI dev-tool marketing" genre at first glance — the site is betting a skeptical visitor reads past the fold before judging.

**Deterministic scan**: `detect.mjs` on `index.html` + `install.html` exited 2 with 8 findings: 2× `overused-font`, 1× `single-font`, 1× `design-system-color`, 3× `design-system-radius`, 1× `em-dash-overuse`. Two are real, actionable drift: `install.html`'s inline `<style>` block introduces `border-radius: 6px`/`10px` (lines 150, 159, 182) outside DESIGN.md's documented `8/12/16/20px` scale, and an undocumented `rgba(255,255,255,0.06)` (line 148) not in the palette. This directly corroborates something Assessment A flagged independently as a maintainability risk (install.html duplicates shared styling in its own inline block instead of `styles.css`) — two independent methods converging on the same root cause raises this from a minor note to a real Priority Issue below.

The `overused-font` flag on Inter is a true positive technically (Inter is on the reflex-reject list for greenfield brand work) but not actionable here: DESIGN.md already commits Inter as the established, shipped typography identity, and per the register's own identity-preservation rule, existing brand commitments aren't second-guessed by this rule. Treat as accepted, not a fix.

Two findings are false positives, traced to the detector's own logic rather than assumed: `single-font` on `index.html` only happens because the regex captures just the first `family=` param from the Google Fonts URL and doesn't follow the linked `styles.css` where JetBrains Mono is actually declared and used in the hero code block — index.html is genuinely two-font, same as install.html. And `em-dash-overuse` ("23 em-dashes") is inflated: ~15 of the 23 are `--` CLI flags inside `<pre>/<code>` blocks (`cargo build --release`, etc.) that the tag-stripping step can't distinguish from prose, and the remainder are doubled by the EN/IT duplicate-DOM-text pattern — true prose em-dash usage is closer to 4 instances.

## Overall Impression

The site earns real credit for actually enforcing its own design system — the DESIGN.md's rejection of glass/gradient decoration shows up as verified zero-instances in the CSS, which is unusual discipline. The gap between "avoids every named slop tell" and "still reads as a template at a glance" is the core tension here: the aesthetic register itself (dark void, cyan glow, blur badges) is now a genre, even when well-executed. The single biggest opportunity isn't visual — it's narrative consistency: the roadmap's flat "100%" phase completions are directly contradicted by the changelog's own admissions of silently-broken code paths shipped well past those marks, and that's exactly the kind of inconsistency this site's stated skeptical-developer audience is primed to catch.

## What's Working

- **The design system's stated constraints were actually honored in code, not just described.** Verified by grep: zero gradient-text occurrences anywhere, exactly two `backdrop-filter` uses, both matching the "one earned surface + one functional nav blur" rule.
- **`prefers-reduced-motion` is handled defensively, twice, with intent.** Scroll-parallax/mouse-tilt handlers are never attached under reduced motion (not just visually suppressed), and there's a documented force-reveal fallback for headless/prerender contexts — more rigorous than typical.
- **The changelog is a genuinely rare, credible artifact on its own terms.** Specific, self-critical technical writing ("silently dropped," "had not actually compiled since Phase 3") reads like a real commit log and directly serves the stated goal of letting a visitor "know the current build status without digging."

## Priority Issues

**[P1] Feature grid is the exact anti-pattern the project's own spec names and rejects**
- **Why it matters**: Four structurally identical icon+heading+paragraph cards (`index.html:130-165`) sit right after the hero — the weakest, most "templated" surface on the page, directly contradicting PRODUCT.md's own Anti-references section.
- **Fix**: Give each feature a differentiated proof artifact (a short real code snippet, terminal output, or roadmap cross-reference) instead of a fourth paragraph of prose, mirroring the credibility treatment the hero code showcase already earns.
- **Suggested command**: `/impeccable shape`

**[P1] Roadmap "100%" phases are contradicted by the changelog's own text**
- **Why it matters**: Phases 0-4 read as flatly 100% complete (`index.html:188-238`), but the Build 36/37 changelog entries admit `obj.field = x`/`arr[i] = x` assignment and the LLM native backend were silently broken well past those marks. The site's most credible artifact undercuts its own status panel — exactly the inconsistency a skeptical developer audience is designed to notice.
- **Fix**: Re-label the metric (e.g. "spec complete" vs. a separate "hardened" indicator) or add a one-line caveat clarifying what the percentage measures, so roadmap and changelog tell one consistent story.
- **Suggested command**: `/impeccable clarify`

**[P1] Hero code showcase has no overflow escape valve at narrow viewports**
- **Why it matters**: `.code-showcase` is `overflow: hidden` with no `overflow-x: auto` on `.window-body`/`.window-body pre`; at the 480px breakpoint the font shrinks to 0.75rem right at the edge of the longest hero code line's width — silently clipping the one component DESIGN.md calls the credibility anchor. `install.html`'s own `.code-block` already uses the correct pattern elsewhere in the same codebase.
- **Fix**: Add `overflow-x: auto` to `.window-body` (or the `pre`), matching the install page's existing pattern.
- **Suggested command**: `/impeccable harden`

**[P2] install.html's inline styles have drifted from the documented design-token scale**
- **Why it matters**: Confirmed independently by both assessments — Assessment A flagged install.html duplicating shared styling in its own inline `<style>` block as a maintainability risk; the detector found the concrete consequence: `border-radius: 6px`/`10px` outside DESIGN.md's 8/12/16/20px scale and an undocumented `rgba(255,255,255,0.06)` color, all only three lines away from values that would have matched had they lived in `styles.css`.
- **Fix**: Move install.html's inline `<style>` block rules into `styles.css`, snapping radius/color values onto the documented tokens.
- **Suggested command**: `/impeccable polish`

**[P2] Changelog renders 37 releases as one flat, ungrouped list**
- **Why it matters**: No year/version grouping, no per-entry collapse — the single biggest chunking violation on the page by the cognitive-load checklist, and it only grows with every future build.
- **Fix**: Group by year or minor version with a "show earlier releases" affordance, keeping only the current and last few builds expanded by default.
- **Suggested command**: `/impeccable distill`

Also would find the hero code-showcase overflow clipping immediately by resizing to 375px/320px, and would hit the unbroken wall of 37 unequal-length changelog entries with no jump-to-version.

**Casey (Distracted Mobile User)**: Both hero CTAs ("Explore Documentation" and "View on GitHub") are `target="_blank"` — 100% of the hero's actionable elements throw a distracted mobile visitor into a new tab before they've scrolled to see any of the credibility content (roadmap, changelog) on the same page. Combined with the mobile-stacked layout pushing the code showcase below the hero text, Casey is the persona most likely to never see the credibility anchor at all.

## Minor Observations

- `--violet: #7000FF` is defined but never referenced anywhere else in the codebase — the "cyan/violet accent pair" both PRODUCT.md and DESIGN.md describe is only half-delivered; there's currently no hero ambient glow at all.
- The four feature-card emoji icons render with OS-dependent native color sets, working against DESIGN.md's "one restrained glyph treatment" intent even with no CSS color applied per-card.
- The `.title` window-chrome label ("main.kix") computes to ~3.16:1 contrast (#666 on #151520) — below the WCAG AA 4.5:1 baseline PRODUCT.md itself commits to. Body/muted text elsewhere checks out fine (~6.9-7.2:1).
- Download buttons default to a dead `href="#"` until the async GitHub API fetch resolves, with no visible loading state — a fast click before that resolves is a silent no-op.
- Hardcoded `rgba(...)` values in install.html re-derive the `--warning`/`--success` hex colors by hand instead of via an RGB-triplet custom property — works today, but a future palette tweak would silently desync these.
